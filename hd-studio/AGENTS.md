# HD Studio operational guide

Read root AGENTS.md and shared/guardrails.md before any mutation. Follow upstream autonomy, workflow and card contracts when handing work to upstream skills. HD rules supplement, never relax, those contracts.

## Workflow

- Input: a prospect, brief, or explicit request to resume one stage.
- Identify the target client workspace; never confuse it with the pipeline repository. Default to private or local client data. Do not infer approval to place documents in a public repo.
- Read STANDARDS.md, then the matching skills/<name>/SKILL.md within hd-studio. Outputs go to `docs/hd/` in the target workspace unless an existing approved path applies.
- Check prior artifacts for duplicate work. Mark information as confirmed, publicly sourced, proposed, or unknown. Preserve source URLs and verification dates in private notes.
- Default communication language: Brazilian Portuguese unless otherwise agreed.
- Invoking a stage authorizes the stated internal analysis and preparation, not outreach, purchasing, publishing, deployment, or production changes. Get explicit approval for those actions.
- If a capability or evidence is missing, record the blocker and offer a precise next action. Do not invent results, claim a deployment, or report a test as passed without evidence.
- Never expose private client data, credentials, or unapproved assets in shared output. Use synthetic fixtures in public examples.

## Handoff

Report status (ready / needs-review / blocked), artifacts, verified checks, outstanding risks and next stage. For engineering tasks use the upstream five-section card format and PR review policy.
