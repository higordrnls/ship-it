# Build preview

Read HD guide, standards, brief, design and existing target code. For a new target, run upstream groundwork and make-guidelines as appropriate. Use upstream create-product to record goals, boundaries and acceptance criteria, then create-tasks to split work and obtain its required task preview confirmation. Execute selected cards through do-task only after their prerequisites are satisfied. Do not bypass protected paths or the dependency approval policy.

Favor the existing stack. For greenfield, propose a static HTML/CSS/JS page unless agreed requirements justify more. Separate verified business content from styling and section components. Build responsive hero, services, portfolio or labeled placeholders, contact and footer. Do not hardcode unverified facts or secrets.

Validate build and relevant tests, inspect rendered pages and record limitations. Produce a local preview or source artifact; deployment is a separate explicitly authorized step. Never imply the prospect owns or approved the preview. Handoff to audit-website.
