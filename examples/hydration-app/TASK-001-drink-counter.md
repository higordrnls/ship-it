## What this card solves

Implements the "Drank" logging slice of the hydration app: one tap records a glass of water, updates today's progress against the daily goal, and persists locally. First slice because every other feature (notifications, dashboard) reads this data.

We store entries as timestamps (not a bare counter) so history and the future dashboard come free; the alternative — a single integer — was rejected because it can't answer "when did I drink". Rollover happens at local midnight using the browser timezone.

Users get instant feedback on progress; the notification slice (TASK-002) will reuse this same log to reset its timer.

## Attention points

- ❌ No direct `localStorage` calls outside the wrapper. ❌ No UTC date math for rollover — user's local timezone.
- Double-submit risk: rapid repeated clicks must not double-count — debounce at the handler (see Test criteria #3).
- Backward compatibility: additive feature, no existing data shapes change; rollback = revert the PR, stored entries are forward-compatible.
- Corrupted storage payload must reset gracefully (warn, don't crash) — users lose history, never the app.
